# iPhone 历史记录重复及失效路径

用户报告两条第 615 集历史，其中一条无法播放。只读取 Orvex 自身偏好和导入目录的文件信息：两条历史指向同一个 `Imports/media-…/…0615….mkv`，区别是旧的应用容器 UUID；实际只存在一份可读的视频，930645737 字节。未复制视频或字幕，也未从主机覆写设备偏好。

根因是历史记录和进度以前使用绝对 URL 作为身份。更新后重开同一文件会产生不同身份，旧 URL 不能继续作为有效文件地址。文件定位现在每次通过当前应用目录解析，符合 [Apple 文件系统指导](https://developer.apple.com/documentation/foundation/using-the-file-system-effectively)中通过目录 API 获取文件位置的方式。

修复行为：

- 已导入文件以相对位置作为稳定身份；记录打开前解析为当前有效地址。
- 历史 v2 按身份合并，保留最近观看时间及对应进度；相同名称但不同副本的记录保持独立。
- 播放进度迁移到稳定键。初次诊断中较新记录约 33 秒、较旧约 43 秒，回归测试验证不能以最大进度替代最近状态。
- 旧历史和进度的 v1 偏好保留为恢复数据，不修改媒体文件。
- 文件确实缺失时在播放前提示，不再直接把旧绝对路径交给播放内核。

47 项测试通过、静态分析通过；新增覆盖目录实际重命名后恢复文件、历史重定位合并、同名不同副本、最近进度迁移、完成后从零开始及单一旧检查点迁移。模拟器原生播放/字幕/跳转/全屏/进度恢复回归通过，模拟器声音仍为 Not Tested。

修复版已签名、覆盖安装并启动。再次读取 Orvex 自身偏好，确认历史 v2 只有一条 615 集记录，指向当前目录；v1 的两条原始记录仍作为恢复数据保留。v2 已出现时间晚于 v1 的新播放检查点，因此该快照不能用来逐值比较迁移前后的进度；进度迁移规则由回归测试验证，实际续播由用户确认。摘要见 `migration-after.json`。
