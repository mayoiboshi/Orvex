# Bangumi 番剧元数据

基于用户指定的 [bangumi/api](https://github.com/bangumi/api)，使用公开 HTTP 接口，代码为 Orvex 自行实现。没有将文档仓库当作服务端运行，也不需要用户提供 Bangumi 账号或令牌。

## 当前行为

- 首次载入媒体库及导入视频后，在后台整理文件名并查询番剧资料；播放不会等待网络。
- 清理常见字幕组、画质、编码、语言标记，解析常见集数、`SxxExx`、年份；支持中文、原名和 API 返回的别名匹配。
- 支持长篇番剧的四位集数，如 `Detective Conan 0615` → 片名 `Detective Conan`、第 615 集；裸露的 `19xx/20xx` 年份不默认当作集数，明确的 `E2023` 等集数标记仍按集数处理。
- 作品自动关联按当前规则默认采用返回候选首项，匹配有误时可手动更正或忽略。
- 当英文系列名未收录在 TV 条目的别名中时，可从最多三个同系列剧场版查询 Bangumi 明确的“主线故事”关联：至少两个独立条目共同指向唯一的 TV 正篇、原名系列前缀一致，且文件有第 2 集或以后的集数提示，才允许据此自动匹配。交叉作品、多主线及季数不明确仍不自动选择。关联依据单独缓存并在资料面板标注，不伪装成 API 官方别名。
- 媒体库、最近添加、继续观看及历史记录展示匹配标题和已缓存封面。资料面板展示原名、中文名、简介、放送日期、评分、总集数及 Bangumi 条目来源链接。
- 点封面上的资料按钮或长按视频，可手动搜索、更正或选择“不关联此视频”。人工关联与忽略不会被后台结果覆盖。
- 播放详情页在已有 Bangumi 作品关联、且已解析本地集号时，通过 [单集接口](https://github.com/bangumi/server/blob/master/openapi/v0.yaml) 分页读取正片。只采用 `sort` 或 `ep` 能唯一对应的候选，优先显示中文单集标题，日期、时长和简介按实际返回显示。缺少简介时省略。
- 不同发行版的编号可能不同。播放详情页可按集号或标题手动更正，选择按视频稳定身份与作品 ID 保存，清除后恢复默认行为。手选结果可离线查看，自动获取的章节表按作品在本次会话内复用。没有自动换算发行版编号，单集关联不改变播放队列、文件名或进度。
- 设置 → 番剧资料 → 自动匹配番剧，可关闭后续自动查询。已缓存的资料仍可查看；用户主动进行的手动搜索不受该开关限制。
- JSON 元数据及封面分别持久化到应用支持目录。封面由同一网络模块下载，并按条目 ID 复用；重启后可在离线状态读取已有资料和封面。
- 仅发送整理后的查询片名及必要 API 参数，不上传视频、字幕或本地路径。原文件名、文件内容和播放进度的键不因元数据关联而改变。

## 接口与网络

采用 [`POST /v0/search/subjects`](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)，`type: [2]` 限定动画，按 `match` 排序，每次取前 10 项。搜索响应包含大部分条目资料；满足上述前提时再通过 `GET /v0/subjects/{id}/subjects` 和 `GET /v0/subjects/{id}` 核实主线关联。封面取响应中的 HTTPS 图片地址。使用 [官方建议](https://github.com/bangumi/api/blob/master/docs-raw/user%20agent.md)格式的开发者/应用/版本 User-Agent。

请求串行并设置最小间隔；重复集数复用片名搜索结果，同一条目复用封面。失败不会在每次切换页面时反复请求；无结果和待确认结果缓存 7 天，失败自动重试至少间隔 15 分钟。手动“重试”保留已有正确关联及人工选择。对 429 尊重 `Retry-After`，超时或服务异常显示可重试状态。

正式 App 使用设备自己的网络/VPN，不将 Mac 的 `127.0.0.1:7892` 写入手机。模拟器联网测试通过测试专用参数将 HTTP 客户端指向用户提供的 Mac 代理，封面和 API 使用同一客户端。正式构建不包含这一测试代理配置。

元数据和封面的来源在界面标注为 Bangumi，相关资料和图像权利归其各自权利人；此集成不主张取得第三方内容所有权。

匹配规则版本更新后会重新处理旧的待确认项，以及提取片名发生变化的自动结果；已匹配且片名提取未变的缓存仍可直接使用，避免升级后离线丢失资料。用户手动选择及“不关联”保持不变；应用重启后会恢复未完成的匹配队列。无需重新导入视频。

## 已验证与边界

- 本模块及柯南修复阶段曾通过 41 项测试与静态分析；工程当前完整检查结果见 [工程基线](verification/engineering-baseline/README.md)。
- iPhone 和 iPad 模拟器均通过真实 API 验证：生成素材使用番剧格式文件名，自动关联《葬送的芙莉莲》（400602），显示真实封面、标题、集数及简介；重建控制器并使用不可达网络后，从本地恢复元数据和封面。
- 测试覆盖同名歧义、季数/年份/集数冲突、别名、手动覆盖与后台请求的竞争、取消关联、网络失败重试、请求过滤/请求头、429、记录及封面缓存。
- 加入元数据模块后，iPhone 模拟器原生播放回归通过。模拟器声音仍为 Not Tested，先前用户自备媒体的真机播放验收独立保留。
- 用户截图报告 `[Fabre–RAW] Detective Conan 0615 [NetflixJP] [1080p].mkv` 查询包含 `0615`，且候选主要为剧场版。修复后以相同文件名、隔离生成素材在 iPhone 模拟器真实联网复验：自动识别 TV 正篇 899、显示第 615 集及封面，并验证旧待确认缓存自动迁移与离线重建。同日用户在自己的 iPhone 和原文件上确认“已正确显示番剧名和封面”，该案例为 Passed（用户实测）。
- 复杂发布组命名、所有字幕组、罗马字变体及一般识别准确率为 **Not Tested**。单集自动匹配以 Bangumi 的编号为准，不能推断不同发行版的编号。
- 此次自备柯南文件在 iPhone 上的自动匹配与封面已获用户确认；其他文件覆盖率、真机离线缓存、iPad 真机及性能仍为 **Not Tested**。不会在物理设备运行或导入测试素材。
