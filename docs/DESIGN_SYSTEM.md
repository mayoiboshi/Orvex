# Orvex 视觉系统 · 第一轮

更新日期：2026-11-06。本文维护已实施的视觉规则；产品构想见 [PRODUCT_VISION](PRODUCT_VISION.md)，实际能力及优先级见 [ROADMAP](ROADMAP.md)。运行结果和截图单独记录在 [视觉验证](verification/visual-system/README.md)。

## 方向与范围

内容优先、克制的科技感：冷白/石墨与蓝黑/银灰构成明暗两套背景，少量冷蓝用于主要操作和选中态。系统字体、轻边界、低强度透明层与紧凑的信息层级形成品牌语言。此前金色、棕绿渐变和装饰光晕不再作为全局设计方向。

本轮落地全局主题、首页、四模块导航、媒体库、播放记录、设置、Bangumi 资料面板及播放器控制层。保留媒体来源、播放会话、引擎、历史和续播逻辑，不引入 UI 框架、状态框架或新依赖。

## 实现选择：Flutter 材质，非原生 Liquid Glass

- 已核对本地 Flutter 3.47.9 / Dart 3.13.7 与现有依赖，没有第三方玻璃/UI 框架需要升级或维护；media_kit 的内置控制层已关闭，当前展示由 Orvex 自己实现。
- Apple 的 [UIGlassEffect](https://developer.apple.com/documentation/uikit/uiglasseffect) 从 iOS/iPadOS 26 提供；[SwiftUI glassEffect](https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)) 是另一条原生路径。当前 iOS 最低目标为 15.0，需要兼容回退。
- 嵌入 UIKit/SwiftUI 还需考虑 [Flutter Platform Views 的合成与性能边界](https://docs.flutter.dev/platform-integration/ios/platform-views)，以及视频、命中区域、布局和跨平台差异。本轮没有引入原生玻璃视图或复杂桥接。
- 第一版 `GlassSurface` 使用裁剪后的 BackdropFilter、半透明底色、轻边缘高光；它是 Flutter 的玻璃风格材质，**不是 Apple 原生 Liquid Glass，没有真实折射或原生材质融合**。未来替换实现保留相同语义入口，届时单独评估，不预先搭插件框架。
- 根据 [BackdropFilter 官方说明](https://api.flutter.dev/flutter/widgets/BackdropFilter-class.html)，模糊须限制在裁剪区域。首页、海报墙、普通卡片和悬浮导航不使用背景模糊。播放器可见时只有顶部、中央和底部三个局部区域使用模糊，隐藏后不绘制。

## 外观与无障碍

- 默认跟随系统；设置提供跟随系统、浅色、深色，切换立即生效。选择使用 SharedPreferences 的 `orvex.appearance.theme.v1` 保存；未知值回退 System。
- 主题加载与用户操作分开计次，较晚完成的读取不能覆盖用户新选择；写入串行，失败保留当前视觉并显示保存问题。主题变化不替换播放会话或视频引擎。
- 应用内“减少透明效果”保存在 `orvex.appearance.reduce-transparency.v1`。系统减少透明度、应用开关、较高对比度或辅助导航启用时，玻璃改用实色并停止背景模糊。
- Flutter 当前没有独立的系统“减少透明度”字段，因此使用小型 `dev.orvex/appearance` 通道读取 Apple 无障碍偏好并监听变化。它只传递布尔设置，不创建原生玻璃视图。
- iOS 依据 [UIAccessibility](https://developer.apple.com/documentation/uikit/uiaccessibility/isreducetransparencyenabled) 与对应通知；macOS 依据 [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency)。减少动态结合系统原生偏好、Flutter accessibilityFeatures 和 MediaQuery，关闭主要主题、控制层、导航与面板动画。
- Android/Windows 无额外原生无障碍桥接；使用 Flutter 提供的设置与应用内透明度开关。相应宿主尚未实际验收。
- 状态栏与系统导航区由主题对应的 SystemUiOverlayStyle 协调；全屏仍保留已有原生全屏行为。

## 页面与平台规则

- 首页：真实续播记录作为主卡，展示封面、标题、当前进度与“继续播放”；其余续播记录统一使用横向内容轨道。没有进度时提供实际导入入口，不填充虚构内容。
- 首页已有当前视频的续播入口时不重复显示迷你播放器；其他页面仍可返回当前播放。近期添加排除主续播卡中的同一文件，保留媒体库入口与搜索。
- 媒体库：按可用宽度调整封面列数；真实缓存封面优先，缺图使用中性的文件占位，不生成假海报或装饰性彩色卡片。资料、更正、搜索与长按入口保持可用。
- 导航：手机和平板采用四模块浮动导航，预留内容底部空间；宽度至少 1000 的桌面窗口采用侧栏。桌面不是手机页面等比放大，主内容设最大宽度，设置页限制阅读宽度。
- macOS 最小窗口 420×480；Android/Windows 的原生窗口、系统栏和返回行为需要在对应宿主后续验收。
- 播放器：局部悬浮玻璃条替代全屏大面积遮罩；中央按键采用轻量胶囊组；进度条闲置 2、拖动 4，滑块同步突出。保持 3 秒隐藏、拖动目标、倍速恢复、亮度/音量、轨道/字幕和键鼠逻辑。

## 首页第一轮像素精修

- 保留品牌/首页标题、主续播卡、横向续播、媒体库、最近添加和四模块导航。首页标题采用 24 点中等字重；副标题展示已有视频和可续播数量，搜索/添加收为同一轻量工具组，其他页面标题规则不变。
- 主卡海报与左边缘融合，卡片半径 18；作品名、集号、真实元数据与进度分层，2 点进度线，胶囊形主操作。正常 iPad 样本由约 244 点高收紧至 196 点；长标题、大字体按内容增高，继续保留左海报/右信息。
- 续播轨道统一封面圆角、两行标题占位及细进度线；最近添加保持原数据顺序、网格和开播/资料动作，标题区固定两行排版高度，年份/评分/来源使用辅助文字。没有改变剧集聚合、历史筛选或缓存格式。
- 媒体库总入口以现有视频封面叠层增强内容感，保留本地视频数量、保存位置及整卡跳转；无媒体时使用原有语义图标，不填充虚构封面。
- 悬浮导航宽度上限 500，正常 iPad 主体高 52（此前 560×71）；图标 21，选中态用图标、文字及细标记，不铺大面积底块。宽度充足时图文横排，窄窗口/大字体纵排，点击区域至少 44 点。共享导航在四个模块统一生效。
- 首页卡片和工具组不使用模糊，只有导航使用受控 Flutter 玻璃，透明底和边界进一步减轻；减少透明度、高对比度与减少动态效果沿用已有规则。不是原生 Liquid Glass，未来材质替换仍通过现有 GlassSurface 抽象进行。

真实前后截图及验证边界见 [首页精修验证](verification/home-polish/README.md)。

### iPad 首页布局与滚动细化

- 根据窗口约束收放页面边距。宽窗口对齐标题与统计的文字基线，窄窗口或大字体时堆叠。搜索和添加共享图标尺寸、圆角及至少 44 点的触控区。
- 主续播卡在宽窗口并排摆放海报、信息与播放按钮，进度区最多 560 点。紧凑布局将按钮放回信息区。其余续播另列一条横向轨道，时间允许换行。媒体库卡片宽窗口分开放置来源与数量，整卡仍可进入媒体库。
- 最近添加按内容宽度与文字缩放决定列数，保留 2:3 海报、两行标题和真实元数据。资料按钮缩小图标与底色范围，保留触控面积。
- 悬浮导航采用语义半透明底色和边框，无实时模糊。减少透明度及高对比度使用实色。首页滚动底距读取 Scaffold 报告的底部占用高度，再留 20 点间距。

### iPad 首页第二轮视觉精修

- 首页标题、分区标题和辅助统计分别采用主题的 `headlineLarge`、`titleMedium` 和 `bodySmall`。统计放在页面标题下方，续播轨道沿用分区标题。
- 内容宽度至少 950 点且字体规模允许时，续播主卡与横向轨道并排；紧凑窗口或大字体回到上下布局。横屏样本主卡为 224 点高，播放按钮紧邻进度，紧凑窗口下放在进度下方。最近添加位于媒体库入口上方。
- 当前 Bangumi 模型只保存作品封面。续播轨道优先使用已有本地预览能力生成的视频帧，取不到时按原比例显示封面。海报不随文字高度拉伸。媒体库数量和保存位置合为副标题。
- 四个模块共享更薄的悬浮胶囊、半透明底色、淡边框和轻底色选中态。图标与文字在触控区垂直居中。常规宽屏导航主体为 48 点，窄窗口和大字体可增加高度；各标签沿用同一布局和至少 44 点的触控区域，滚动底距按实测高度预留。

### 最近添加的封面

- 最近添加使用响应式左对齐网格。作品、已匹配的剧场版及 Bangumi 单话 WEB 作品使用填满的 2:3 竖版海报，其他单集、普通视频和类型未确认的文件使用 16:9 横版图片区。混排沿用原排序，同行卡片顶部对齐。
- 单集及普通视频优先复用续播缩略图。剧场版海报缺失或无法解码时可在竖框中等比显示本地帧。失败时使用占位图，图片区在异步加载期间保持原尺寸。标题最多两行，时长角标仅显示已有的观看记录、目录或提帧时长。

### 最近添加的作品卡

- 首页用已确认的 Bangumi 作品 ID 聚合单集，独立电影和归属不明确的文件各自显示。先用完整目录组成作品，再截取首页卡片。作品卡将年份和评分与本地收录的视频文件数分行显示。
- 作品按组内最新加入时间排序。升级前的文件以修改时间辅助排序；之后以导入副本写入时间或授权目录首次索引时间排序。时间记录以稳定文件身份单独保存。
- 点作品卡进入首页导航栈中的详情。详情复用单集横向预览、资料和观看进度，直接点单集播放。退出播放时保留作品详情。

## 播放详情页边界

- 普通页面背景由安全区外的根 Scaffold 铺满窗口；SafeArea 保护内容，不为安全区另绘黑色背景。全屏的视频黑底及片源宽高比留黑独立保留。
- 非全屏视频按实际窗口适配：iPad 及左右分栏模式不保留视频外侧装饰留白和圆角，视频靠内容左边界；短窗口因高度约束变窄时仍靠左，不强行拉伸。文字和控制按钮继续遵守安全区与内边距。手机窄于 600 时贴边；桌面原上下布局保留 12/20 点留白和 10 点圆角。iPad 页面不套桌面最大宽度。历史规则见 [布局验证](verification/player-layout/README.md)，当前贴边修正见 [贴边验证](verification/wide-player-edge/README.md)。

## 宽窗口播放布局

- 仅桌面及显示屏短边至少 600 逻辑点的 iPad 提供宽屏切换，可用内容宽度须至少 1000；手机、窄分屏/窗口保持原上下布局，无无效按钮。
- 空间足够时默认窄屏模式：左侧视频和资料，右侧 336–392 点的播放列表，列表独立滚动。宽屏模式返回原视频、资料、列表上下排列，独立于全屏。
- 播放控制条中宽屏按钮位于全屏按钮前，选中态与提示表明当前模式。缩小窗口只临时回退，不覆盖本次页面的模式选择；本轮没有新增持久偏好。
- 原列表组件继续负责搜索、筛选、定位、选集与目录切换；布局切换保留列表状态，回到宽屏时滚动至顶部以露出视频。非全屏视频子树保留挂载，既有引擎、进度、字幕和手势不因布局切换重置。全屏沿用原有流程。证据及平台边界见 [宽屏验证](verification/wide-player/README.md)。

## 大屏播放页精修

- 顶栏主要展示已关联作品名或已有剧集名称，来源作为次级一行；原始文件名保留在文件详情中。返回、更多、帮助、添加保持原动作和 44 点触控区域。
- `WatchInformation` 只呈现标题、集号、进度、Bangumi 入口及播放顺序操作；命令和偏好写入仍由 PlayerPage 承担。足够宽时信息居左、前后集与自动下一集居右；窄屏或大字体改为上下排列。Bangumi 使用轻边界次级按钮，前后集采用同一轻量操作组，自动下一集文字与开关成对显示。
- 播放列表继续惰性构建，观看列表行基础高度 120 点，随文字缩放；16:9 缩略图占行宽约 35%，限制 116–156 点；标题、时长/大小、观看状态分层。当前项使用柔和底色、3 点强调条、静态播放标记及选中语义，不引入持续动效或列表模糊。
- 右侧工具栏固定，保留目录/剧集切换、搜索、定位；从中途打开搜索会滚到搜索框，滚动列表不移动左侧视频。原上下布局仍整体滚动。
- 三处悬浮控制层使用 `GlassSurface.subtle` 降低透明底层与边界强度，中央播放区稍缩小，保留至少 44 点的操作区域。控制层在视频内留出安全间距；没有恢复视频外侧留白、圆角大卡片或全宽遮罩。减少透明度/高对比度回退沿用原规则，没有新增模糊区域；仍为 Flutter 材质，非 Apple 原生 Liquid Glass。

运行截图、功能与平台边界见 [精修验证](verification/player-polish/README.md)。

## 页面返回

- 二级页面在 iOS/iPadOS 使用 Cupertino 页面的跟手边缘返回，取消则回弹；同级底部模块不制造返回历史。Android 使用系统返回；桌面支持 `⌘[` / `Alt+←` 和鼠标返回侧键。
- 确认离开播放页才暂停/保存，取消不暂停；全屏保留播放器横滑，退出方式沿用当前控制。前页保留滚动、筛选与选择，页面底色采用同一语义背景。详见 [返回验证](verification/back-navigation/README.md)。

## 维护边界与后续

只为已复用的视觉行为增加共享组件，不创建空的设计组件目录或第二套主题状态管理。当前外观控制器沿用 ChangeNotifier 与 Riverpod 装配，只管理外观，不进入播放会话。

- iOS/iPadOS 启动器使用「切环 Orbit Cut」的原生 Icon Composer 文件 `ios/Runner/AppIcon.icon`。背景、主体矢量及外观在同一文件维护，由 Xcode 按部署目标生成旧系统图标。
- 应用内的 `OrvexBrand` 使用同一切环轮廓的单色透明素材，按主题强调色显示。播放器中的播放三角保留操作语义。
- 应用内原生 Liquid Glass、更多原生平台交互及移动端性能和功耗仍待验证。macOS 现有出站网络授权缺口见验证记录。
