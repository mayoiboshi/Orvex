# 产品路线图与能力现状

更新日期：2026-11-06。长期目标为 iOS、Android、macOS、Windows；当前交付优先 iOS/iPadOS。本文是当前能力的主清单，记录阶段、优先级、状态和下一步目标。完整功能构想见 [PRODUCT_VISION](PRODUCT_VISION.md)，实际架构见 [ARCHITECTURE](ARCHITECTURE.md)。代码“已实现”不等于所有格式、设备或平台都已验收；详细历史证据见 [验证状态](verification/STATUS.md)。

## 阶段与优先级

阶段表示推进方向，不是开发任务或日期承诺。当前仍以阶段一为主，已有部分阶段二能力；不能因首页和封面已出现，就判定媒体库阶段完成。阶段间可按实际需求小步交叉，后期能力不挤占基础播放体验。

优先级：**P0 当前重点**、**P1 基础稳固后的近期候选**、**P2 后续候选**、**P3 远期研究**；它们不等于已排期。状态中「部分实现」表示只有一部分行为落地，「未实现」表示没有对应产品能力，「待调研」表示技术方案或可行性未确定。多种状态可以并存。具体实现证据集中在下方能力表。

| 阶段 | 目标范围 | 当前状态 | 优先级与推进条件 |
| --- | --- | --- | --- |
| 一：本地播放体验 | 文件导入/管理、基础控制与进度、音量/亮度/手势、字幕/音轨/设置、格式/记录/稳定性、五类设备适配验证 | 部分实现；核心播放已有 iPhone 反馈，文件管理和部分控制待完善，多平台未全面验收 | **P0**；先补 iOS/iPadOS 设备证据和可靠性，其他平台按后续任务安排 |
| 二：媒体库 | 首页/海报墙/详情/动画、影视资料与系列归档、搜索/筛选/收藏/继续观看、本地远程统一管理 | 部分实现；已有四入口、网格、搜索、Bangumi 资料、继续观看和首页最近添加的作品聚合；作品视图支持排序、类型筛选及紧凑列表，目录视图保留未播放筛选；收藏及远程统一管理未实现 | **P1**；先解决真实片库中的查找、整理和性能问题；完整归档及统一模型待调研 |
| 三：多数据源聚合 | NAS/WebDAV/SMB、Emby/Jellyfin、TVBox 类适配、第三方与合法成人内容来源、私人媒体库和隐私保护 | 未实现；具体来源、接入与隐私方案均待调研 | **P2**；选一个明确来源验证浏览到播放，再决定扩展方式 |
| 四：下载中心 | HTTP/HTTPS 续传、HLS/DASH、磁力/Torrent、迅雷可选后端与云盘研究、NAS/aria2/qBittorrent、队列/恢复/边下边播 | 未实现；下载后端、平台可行性和任务/存储方案待调研 | **P2**，原则上在来源与播放链路明确后；libtorrent、迅雷 SDK 等均为候选，未选型 |

本轮只维护规划，不将上述阶段拆成已启动任务，也不批准任何候选依赖或服务。

已修复单集重复导入与漏接缩略图，保留历史身份、支持旧导入文件按需补图。iPad 修复版已覆盖安装和启动，真实文件效果待反馈；见 [修复验证](verification/imported-media-fix/README.md)。

**用户指定的文件夹感知媒体库与竖屏详情首版已实现并完成自动检查和模拟器验证。** 保留真实目录层级、稳定身份和旧记录；下一步优先用 iPhone/iPad 自备片库验证外部目录授权、重启恢复和真实格式缩略图。详见 [文件夹设计](folder-library.md) 及其验证记录。

**此前的首轮 UI 优化已实施。** 已建立共享设计 Token、三种外观与受控玻璃材质，并改造四模块及播放器。详情见 [DESIGN_SYSTEM](DESIGN_SYSTEM.md)。接下来优先在 iPhone/iPad 真机验证新视觉、横竖屏、安全区和可读性，再做局部精修；macOS 出站网络配置需单独修复验证，不把离线 UI 通过写成联网通过。

**后续验证建议：补齐 iPad 与 iOS 关键系统行为的最小真机验收。** 核心链路已经能用，先查明实际设备上的问题，比直接叠加数据源或下载入口更有价值。完成条件是形成按设备/系统/媒体样本区分的结果，已执行项有实际反馈，失败项可复现，未执行项仍为 Not Tested；不要求为了勾完表而扩展功能。

## 后续候选，不是已承诺功能

- iOS/iPadOS：文件副本整理、番剧与季度聚合、分集展示；按需求选择小任务，涉及跨模块数据设计时走 L。
- 平台恢复：先准备对应宿主和 SDK，核验 Android 发布网络/签名及 macOS 联网授权，再做最小构建与真实播放；Windows 需要 Windows 开发主机。本轮不安装 Android SDK、不更改原生权限或签名。
- 媒体源和系统能力：NAS/云盘、媒体下载、画中画、投屏等，先明确用户要解决的场景，再按 L 设计；不提前搭插件或任务调度框架。
- 持久化：只有真实容量、查询和迁移需求超过当前实现时再评估数据库；Drift/SQLite 是候选，不是已实施或已确认选择。
- 分发：明确项目许可证与第三方来源清单，区分测试素材和正式资源，补构建/签名说明。自动发布和复杂 CI 暂无必要。

## 规划维护方式

- 功能构想范围维护在 PRODUCT_VISION，完成状态只更新本文；实现事实与验证证据分开记录，不能用计划或测试数量代替真机结果。
- 新任务从当前需求和上述候选中选取小目标，说明可观察结果与验证范围；S/M 沿用简短流程，不增设审批或必写设计文档。
- 新数据源、下载、播放器或跨模块方案按 AGENTS 的 L 级规则先形成设计并确认；规划中的技术名称保持「待调研」，正式采用后才更新 DECISIONS。
- 发生实际交付、验证结论或优先级变化时再更新，不维护第二套任务系统，不提前规定阶段日期。
